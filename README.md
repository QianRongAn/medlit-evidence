# MedLit Evidence

一个医学文献循证问答助手。你问一个临床问题，它去 PubMed 里翻文献，回来只告诉你三件事：

证据站在哪一边，有没有人在唱反调，这个结论值几分可信。

它不给你"标准答案"。大多数 AI 拿到一堆互相矛盾的文献，会替你"和稀泥"，给一个听起来很确定的结论，顺手还可能编几个不存在的 PMID。这个工具反着来，它把分歧摆到台面上，让你自己判断。

零密钥就能跑，断网了也能演示。后端约 400 行 Python，前端一个静态页面，三个依赖。

![运行截图](docs/screenshot.png)

## 它解决什么问题

查一个治疗方案有没有证据，会卡在两个地方。

第一，PubMed 有三千八百万篇文献。搜一个词，回来几十万条结果，没有研究类型标注，没有证据强弱区分，全靠人肉筛。

第二，更麻烦的是另一个问题。等你真把文献读完了，会发现结论互相打架：一篇说有效，一篇说没差异，还有一篇提醒你权衡副作用。通用大模型拿到这种材料，最省事的做法是抹平矛盾、给出确定答案。而循证医学的立身之本恰恰相反：把矛盾讲清楚，而不是假装它不存在。

这就是这个工具在解决的事。它把"搜文献"到"下判断"中间那段最费脑子的活，替你做掉。

## 核心创新：建模证据分歧，而不是给"标准答案"

### 大模型的"假共识"问题

通用大模型回答医学问题，有两个系统性风险：

1. **幻觉**。编造不存在的文献、数据、PMID。
2. **假共识**。把文献里本就对立的结论抹平，自信地给出一个确定答案。

医学编辑、医生、科研人员查文献，很多时候就是为了搞清楚一件事：这件事到底有没有争议。这个产品把这个需求显式地做成了能力，而不是靠模型"顺便"输出。

### 三个能力

**结论极性识别（支持 / 反对 / 中立）**

先抽结论句，再判方向。结论句优先取摘要里带 `CONCLUSIONS` / `FINDINGS` / `INTERPRETATION` 标签的句子，跳过 `DISCUSSION` / `LIMITATION` 段。

极性判定用三层规则，强短语优先，否定词感知：

| 优先级 | 规则 | 判定 |
| --- | --- | --- |
| 1 | 命中强正向短语（`reduced risk`、`improved survival`、`no increase in`） | 支持 |
| 2 | 命中强负向短语（`no significant`、`increased risk`、`failed to`、`inconclusive`） | 反对 |
| 3 | 命中弱正向词（`reduce`、`improve`、`benefit`） | 有否定词 → 中立，否则 → 支持 |

为什么要管否定词？像 `no significant benefit` 这种句子，如果只数正负关键词，会同时命中 `benefit`（正）和 `no significant`（负），打成平手被误判成中立。显式识别否定词之后，才正确地判成反对。

**证据冲突检测**

统计所有结论句的极性，给一个总体判断：

- 同时有"支持"和"反对" → **证据存在分歧**
- 只有"支持" → **证据倾向支持**
- 只有"反对" → **证据倾向不支持**
- 其余 → **证据不足或未明确**

有分歧时，界面会高亮提示"文献结论存在对立，采信需谨慎"，并把正反两边的篇数都列出来。

**证据置信度评分（0-100）**

一个可解释的启发式评分，不是黑箱：

```
置信度 = 证据等级基础分 ± 结论一致性 ± 文献量 ± 时效
```

| 分项 | 规则 |
| --- | --- |
| 证据等级基础分 | High 90 / Moderate 70 / Low 50 / Very low 30 / N/A 40，按全部文献加权平均（不是取最高档，极低/未分级会真实拉低分数） |
| 结论一致性 | 无冲突 +6，有冲突 -10 |
| 文献量 | ≥6 篇 +4，≥3 篇 +2 |
| 时效 | 近 5 年内有文献 +4 |

分数旁边同时展示"支持 / 反对 / 中立"的篇数，所以这个数是可以拆开质疑的，不是凭空蹦出来的。也正因为是加权平均，一篇 meta 分析无法掩盖同期大量低质量证据。

### 一个真实例子

问"他汀类药物会增加新发糖尿病风险吗"，系统输出：

- **判定：证据存在分歧**（支持 1 / 反对 4 / 中立 3）
- "反对"来自多篇 meta 分析，比如 Sattar 2010（PMID 20167359），指出他汀轻微增加新发糖尿病风险
- "支持"来自他汀降低心血管事件的证据

这正是这个领域的真实张力：他汀降心血管事件，却轻微增加糖尿病风险。通用大模型可能直接甩一句"他汀利大于弊"，而这个工具把两边证据都摆出来，留给你判断。

### 和通用大模型的差别

| 维度 | 通用大模型直接回答 | 本项目 |
| --- | --- | --- |
| 结论确定性 | 倾向给确定答案，掩盖争议 | 显式标注"存在分歧" |
| 引用 | 可能编造 PMID | 每句锚定真实 PMID，可点击核对 |
| 证据强弱 | 不区分研究设计 | 5 档证据分级 |
| 可信度 | 无量化 | 0-100 置信度 + 可拆解公式 |
| 可审计 | 难 | 每个结论都能溯源到原文 |

### 边界

诚实地说，它离"严谨的循证工具"还有距离：

- 极性和分级是规则驱动，不是语义理解，复杂句式（比如双重否定）可能误判
- 置信度是启发式评分，不是统计推断，也没做效应量合并
- 抽取式回答只选择和标注已有句子，不生成新推理

这些边界正好指向下一步：向量语义检索、PICO（人群 / 干预 / 对照 / 结局）结构化、效应量合并做真正的定量 meta 分析。

## 核心功能

- 中英文双语提问，70+ 条中文医学术语自动映射成英文检索词（二甲双胍 → metformin，糖尿病 → diabetes）
- 在线检索 PubMed，覆盖 3800 万+ 篇文献；断网时自动回退内置语料，演示不会断
- 问题理解（PICO）：把临床问题拆成人群 / 干预 / 对照 / 结局四要素，再结构化检索
- 9 类研究设计识别（Meta 分析 / 系统综述 / 指南 / 随机对照试验 / 临床试验 / 队列 / 病例对照 / 病例报告 / 综述 / 基础研究）
- 5 档证据分级，结果页展示等级分布
- 结论极性识别，回答的每一句都带方向标注
- 证据冲突检测，有对立结论就明说"存在分歧"，不给假共识
- 证据置信度评分（0-100）
- 撤稿 / 存疑 / 更正检测，问题文献红色标注并降权，不参与结论统计
- 抽取式回答，每个结论句带可点击的 [PMID] 引用
- 进程内 TTL 缓存，重复提问秒回

## 撤稿检测与风险画像

检索结果里如果混入被撤稿、被标记存疑（Expression of Concern）或已更正的文献，系统会：

1. 解析 PubMed 的 PublicationType 和 CommentsCorrections 元数据，识别三类问题文献
2. 在结果卡片上给"已撤稿 / 存疑 / 已更正"红色徽章，并弹出告警
3. 撤稿文献不参与"支持 / 反对"统计，置信度扣 15 分

在这之上，`scripts/` 里还有一个可复现的数据资产管线：

- `collect_retractions.py` 按年份段分层抓取撤稿 / 存疑 / 更正文献 + 正常对照，产出带标签数据集 `data/retraction_dataset.jsonl`
- `profile_retractions.py` 生成 `data/retraction_profile.md`，统计撤稿耗时分布、期刊分布、研究类型分布

这是把"撤稿检测"从一个规则开关，往"撤稿风险预测"推进的地基。数据来自 PubMed 公开元数据，零密钥、可复现。

## 撤稿风险预测模型

数据资产只是地基，这一步把它推到了第三层：训练一个分类器，学习「哪种研究描述更容易翻车」。

三个方法论决策决定了这个模型有没有意义：

1. **重做对照组（matched control）**。最初的 76 篇"正常"论文里混着 33 篇社论和 6 篇新闻，社论本来就不会因数据造假被撤稿，拿它们当负样本，模型只会学到"社论不等于研究论文"这种废话。现在给每篇翻车文献配一篇同刊同年的正常研究论文作对照，180 篇正样本全部匹配成功，其中 179 篇是同刊同年的严格匹配，期刊和年代的混杂被一并排除。
2. **防标签泄漏**。PubMed 的发表类型里直接写着 "Retracted Publication"，把它当特征，模型看一眼就能 100% 分对，等于什么都没学到。所有特征只来自发表时点可得的题录信息：写作特征（标题与摘要长度、句长、数字密度、夸张词、确定性措辞、模糊限定词）、文献计量（作者数、机构数、资助数、参考文献数）、研究设计（从标题摘要文本重新推断，不吃发表类型标签）。
3. **诚实的评估**。5 折分层交叉验证、三个模型对比，不拿单次切分的漂亮数字当结论。

结果（完整实验见 `data/model_report.md`）：

| 模型 | AUC | PR-AUC | F1 |
| --- | --- | --- | --- |
| 逻辑回归（基线） | 0.633 ± 0.068 | 0.611 ± 0.067 | 0.602 ± 0.079 |
| LightGBM | 0.747 ± 0.089 | 0.714 ± 0.098 | 0.712 ± 0.061 |
| 随机森林 | 0.723 ± 0.099 | 0.707 ± 0.094 | 0.697 ± 0.078 |

SHAP 归因给出的发现比分数本身更有意思：翻车文献的题录信息整体「更瘦」。标题中位数 82.5 字符对 110.5，摘要 1148 对 1492，摘要里的数字密度只有对照的一半。同刊同年的对照设计排除了期刊格式和年代差异，这些信号指向同一个方向：写作信息密度不足。而直觉上的"话说得太满"（夸张词、确定性措辞）单项贡献都很小。预示翻车的不是吹嘘，而是内容单薄。

模型的定位是「发现可疑描述模式」的排序辅助，不能判定某篇文献是否会被撤稿，完整局限讨论见实验报告末尾。

## 技术选型

- 后端：FastAPI + Uvicorn（异步）
- 检索：BM25 纯 Python 实现，无 scikit-learn / nltk
- 数据源：PubMed E-utilities（esearch + efetch + elink，免费无密钥）
- 分词：英文按词 + 停用词过滤，中文单字 + bigram，无需 jieba
- 问题理解：PICO 四要素，规则驱动中英文双向词典匹配
- 研究设计识别：标题 + 摘要 + 发表类型的规则匹配，按优先级判定
- 结论极性 / 冲突检测 / 置信度：强短语优先 + 否定词感知，显式建模证据分歧
- 完整性检测：PublicationType + CommentsCorrections 元数据解析
- 答案合成：默认抽取式（证据等级 + 关键词密度 + 结论句加权）；接 OpenAI 兼容接口后升级为生成式
- 前端：原生 HTML / CSS / JS，无框架，无构建

## 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 启动（公司网络 / 沙箱需要代理时先 export PUBMED_PROXY=http://127.0.0.1:7890）
uvicorn app.main:app --host 127.0.0.1 --port 8000

# 3. 打开 http://127.0.0.1:8000/
```

不装密钥也能跑，默认走离线抽取式回答；网络不通时回退内置语料。

### 可选：接 LLM 升级为生成式

```bash
export LLM_API_KEY=sk-xxxx
export LLM_BASE_URL=https://api.openai.com/v1   # 任意 OpenAI 兼容接口
export LLM_MODEL=gpt-4o-mini
```

配置后回答改为生成式（RAG），不配置则自动回退抽取式。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /health | 健康检查，返回 PubMed 是否在线 |
| POST | /api/search | 检索 + 分类，返回文献列表与证据等级 |
| POST | /api/answer | 完整问答，返回回答 + 引用 + 证据结论（极性 / 冲突 / 置信度）+ 证据分布 |

```bash
curl -X POST http://127.0.0.1:8000/api/answer \
  -H "Content-Type: application/json" \
  -d '{"query": "metformin cardiovascular risk type 2 diabetes"}'
```
