# MedLit Evidence

一个医学文献循证问答助手。你问一个临床问题，它去 PubMed 里翻文献，回来只告诉你三件事：

证据站在哪一边，有没有人在唱反调，这个结论值几分可信。

它不给你"标准答案"。大多数 AI 拿到一堆互相矛盾的文献，会替你"和稀泥"，给一个听起来很确定的结论，顺手还可能编几个不存在的 PMID。这个工具反着来，它把分歧摆到台面上，让你自己判断。

零密钥就能跑，断网了也能演示。后端约 400 行 Python，前端一个静态页面，三个依赖。

![运行截图](docs/screenshot.png)

## 一句话看懂它是什么

**这是一个「帮你查医学证据、还帮你判断这份证据靠不靠谱」的助手。**

你问它一个临床问题（比如「这个药到底有没有效」），它替你翻遍几千万篇医学文献，然后不是甩给你一个「听起来很肯定」的答案，而是老老实实告诉你三件事：

1. **证据站在哪一边**：支持的人多还是反对的人多
2. **有没有人在唱反调**：结论是不是互相打架
3. **这个结论值几分可信**：给你一个 0 到 100 的分，以及为什么是这个分

它最特别的地方是：**别的 AI 会「和稀泥」，它专门把「争议」摆到台面上。** 因为它相信，医学决策最怕的不是「没答案」，而是「一个听起来很确定的假答案」。

## 它强在哪（优势）

跟直接用通用大模型（ChatGPT 这类）查医学问题相比，它有几个实打实的优势：

| 对比项 | 通用大模型 | 本项目 |
| --- | --- | --- |
| 给答案 | 倾向给一个「很确定」的结论，掩盖争议 | 明确标出「证据存在分歧」，把正反两边都列出来 |
| 引用文献 | 可能编造不存在的编号 | 每句话都锚定真实的文献编号，可点开核对 |
| 证据强弱 | 不区分「大研究」还是「小报告」 | 按 5 个等级区分证据强弱 |
| 可不可信 | 不给量化分数 | 给 0–100 分，还告诉你这个分怎么算出来的 |
| 能不能追责 | 难，答错了不知道错在哪 | 每个结论都能追溯到具体原文 |

**一句话概括优势：它不装懂，而且每个结论都能让你自己去核实。**

## 它有什么用（用途）

**给谁用：**

- **医生 / 临床工作者**：查一个治疗方案，快速看清「证据到底站不站得住」，而不是被一两篇研究带偏
- **医学生 / 科研人员**：写论文、做综述时，快速摸清某个问题的证据全貌和争议点
- **医学编辑 / 审稿人**：一眼看出某篇文献「有没有被撤稿、风险高不高」

**几个具体场景：**

- 想知道「他汀会不会增加糖尿病风险」——它会告诉你「两边都有证据，存在分歧」，而不是替你拍板
- 检索结果里混进了**被撤稿的文献**——它会用红色标记出来，并且不让这篇坏文献污染结论
- 拿不准一篇论文靠不靠谱——它会给出一个「风险分」，帮你判断要不要重点核查

**更长远的价值**：它不只是一次性问答工具，背后还搭了一套「撤稿风险预测 + 可信性交叉验证」的研究管线，目标是让「一篇论文将来会不会出事」这件事，能被数据提前预警，而不是等出事了才被发现。

## 它解决什么问题

查一个治疗方案有没有证据，会卡在两个地方。

第一，PubMed 有三千八百万篇文献。搜一个词，回来几十万条结果，没有研究类型标注，没有证据强弱区分，全靠人肉筛。

第二，更麻烦的是另一个问题。等你真把文献读完了，会发现结论互相打架：一篇说有效，一篇说没差异，还有一篇提醒你权衡副作用。通用大模型拿到这种材料，最省事的做法是抹平矛盾、给出确定答案。而循证医学的立身之本恰恰相反：把矛盾讲清楚，而不是假装它不存在。

这就是这个工具在解决的事。它把"搜文献"到"下判断"中间那段最费脑子的活，替你做掉。

## 核心创新：建模证据分歧，而不是给"标准答案"

### 大模型的"假共识"问题

通用大模型回答医学问题，有两个系统性风险：

1. **幻觉**。编造不存在的文献、数据、PMID。
2. **假共识**。把文献里本就对立的结论抹平，自信地给出一个确定答案。

医学编辑、医生、科研人员查文献，很多时候就是为了搞清楚一件事：这件事到底有没有争议。这个产品把这个需求显式地做成了能力，而不是靠模型"顺便"输出。

### 三个能力

**结论极性识别（支持 / 反对 / 中立）**

先抽结论句，再判方向。结论句优先取摘要里带 `CONCLUSIONS` / `FINDINGS` / `INTERPRETATION` 标签的句子，跳过 `DISCUSSION` / `LIMITATION` 段。

极性判定用三层规则，强短语优先，否定词感知：

| 优先级 | 规则 | 判定 |
| --- | --- | --- |
| 1 | 命中强正向短语（`reduced risk`、`improved survival`、`no increase in`） | 支持 |
| 2 | 命中强负向短语（`no significant`、`increased risk`、`failed to`、`inconclusive`） | 反对 |
| 3 | 命中弱正向词（`reduce`、`improve`、`benefit`） | 有否定词 → 中立，否则 → 支持 |

为什么要管否定词？像 `no significant benefit` 这种句子，如果只数正负关键词，会同时命中 `benefit`（正）和 `no significant`（负），打成平手被误判成中立。显式识别否定词之后，才正确地判成反对。

**证据冲突检测**

统计所有结论句的极性，给一个总体判断：

- 同时有"支持"和"反对" → **证据存在分歧**
- 只有"支持" → **证据倾向支持**
- 只有"反对" → **证据倾向不支持**
- 其余 → **证据不足或未明确**

有分歧时，界面会高亮提示"文献结论存在对立，采信需谨慎"，并把正反两边的篇数都列出来。

**证据置信度评分（0-100）**

一个可解释的启发式评分，不是黑箱：

```
置信度 = 证据等级基础分 ± 结论一致性 ± 文献量 ± 时效
```

| 分项 | 规则 |
| --- | --- |
| 证据等级基础分 | High 90 / Moderate 70 / Low 50 / Very low 30 / N/A 40，按全部文献加权平均（不是取最高档，极低/未分级会真实拉低分数） |
| 结论一致性 | 无冲突 +6，有冲突 -10 |
| 文献量 | ≥6 篇 +4，≥3 篇 +2 |
| 时效 | 近 5 年内有文献 +4 |

分数旁边同时展示"支持 / 反对 / 中立"的篇数，所以这个数是可以拆开质疑的，不是凭空蹦出来的。也正因为是加权平均，一篇 meta 分析无法掩盖同期大量低质量证据。

### 一个真实例子

问"他汀类药物会增加新发糖尿病风险吗"，系统输出：

- **判定：证据存在分歧**（支持 1 / 反对 4 / 中立 3）
- "反对"来自多篇 meta 分析，比如 Sattar 2010（PMID 20167359），指出他汀轻微增加新发糖尿病风险
- "支持"来自他汀降低心血管事件的证据

这正是这个领域的真实张力：他汀降心血管事件，却轻微增加糖尿病风险。通用大模型可能直接甩一句"他汀利大于弊"，而这个工具把两边证据都摆出来，留给你判断。

### 和通用大模型的差别

| 维度 | 通用大模型直接回答 | 本项目 |
| --- | --- | --- |
| 结论确定性 | 倾向给确定答案，掩盖争议 | 显式标注"存在分歧" |
| 引用 | 可能编造 PMID | 每句锚定真实 PMID，可点击核对 |
| 证据强弱 | 不区分研究设计 | 5 档证据分级 |
| 可信度 | 无量化 | 0-100 置信度 + 可拆解公式 |
| 可审计 | 难 | 每个结论都能溯源到原文 |

### 边界

诚实地说，它离"严谨的循证工具"还有距离：

- 极性和分级是规则驱动，不是语义理解，复杂句式（比如双重否定）可能误判
- 置信度是启发式评分，不是统计推断，也没做效应量合并
- 抽取式回答只选择和标注已有句子，不生成新推理

这些边界正好指向下一步：向量语义检索、PICO（人群 / 干预 / 对照 / 结局）结构化、效应量合并做真正的定量 meta 分析。

## 核心功能

- 中英文双语提问，70+ 条中文医学术语自动映射成英文检索词（二甲双胍 → metformin，糖尿病 → diabetes）
- 在线检索 PubMed，覆盖 3800 万+ 篇文献；断网时自动回退内置语料，演示不会断
- 问题理解（PICO）：把临床问题拆成人群 / 干预 / 对照 / 结局四要素，再结构化检索
- 9 类研究设计识别（Meta 分析 / 系统综述 / 指南 / 随机对照试验 / 临床试验 / 队列 / 病例对照 / 病例报告 / 综述 / 基础研究）
- 5 档证据分级，结果页展示等级分布
- 结论极性识别，回答的每一句都带方向标注
- 证据冲突检测，有对立结论就明说"存在分歧"，不给假共识
- 证据置信度评分（0-100）
- 撤稿 / 存疑 / 更正检测，问题文献红色标注并降权，不参与结论统计
- 抽取式回答，每个结论句带可点击的 [PMID] 引用
- 进程内 TTL 缓存，重复提问秒回

## 撤稿检测与风险画像

检索结果里如果混入被撤稿、被标记存疑（Expression of Concern）或已更正的文献，系统会：

1. 解析 PubMed 的 PublicationType 和 CommentsCorrections 元数据，识别三类问题文献
2. 在结果卡片上给"已撤稿 / 存疑 / 已更正"红色徽章，并弹出告警
3. 撤稿文献不参与"支持 / 反对"统计，置信度扣 15 分

在这之上，`scripts/` 里还有一个可复现的数据资产管线：

- `collect_retractions.py` 按年份段分层抓取撤稿 / 存疑 / 更正文献 + 正常对照，产出带标签数据集 `data/retraction_dataset.jsonl`
- `profile_retractions.py` 生成 `data/retraction_profile.md`，统计撤稿耗时分布、期刊分布、研究类型分布

这是把"撤稿检测"从一个规则开关，往"撤稿风险预测"推进的地基。数据来自 PubMed 公开元数据，零密钥、可复现。

## 撤稿风险预测模型

数据资产只是地基，这一步把它推到了第三层：训练一个分类器，学习「哪种研究描述更容易翻车」。

三个方法论决策决定了这个模型有没有意义：

1. **重做对照组**。最初的 76 篇"正常"论文里混着 33 篇社论和 6 篇新闻，社论本来就不会因数据造假被撤稿，拿它们当负样本，模型只会学到"社论不等于研究论文"这种废话。360 篇试点版给每篇翻车文献配了同刊同年的严格对照；扩到全量后改为按年份分层采样正常研究论文（正 12978 / 负 15000，逐年对齐，排除社论/新闻/信件等非研究类型）。
2. **防标签泄漏（两层）**。第一层是显式的：PubMed 发表类型里直接写着 "Retracted Publication"，把它当特征模型就是开卷考试。第二层是隐蔽的：撤稿记录的摘要常被 PubMed 清空或替换成撤稿声明，"摘要缺失"本身就是泄漏，还顺带污染所有长度类特征。全量版过滤了 4345 篇摘要过短与 277 篇摘要被替换成撤稿声明的记录，并把数字密度改为按千字归一。过滤后标题长度的方向在小样本里反转，证明小样本阶段的"题录更瘦"结论主要是元数据残缺的伪迹，已在报告里更正。
3. **诚实的评估**。5 折分层交叉验证之外，补做了时序外推验证（用 ≤2024 年训练、预测 2025 年后），这是比交叉验证更接近真实使用的检验。

全量结果（23279 篇干净样本，完整实验见 `data/model_report_large.md`）：

| 模型 | AUC | PR-AUC | F1 |
| --- | --- | --- | --- |
| 逻辑回归（基线） | 0.795 ± 0.004 | 0.717 ± 0.008 | 0.677 ± 0.005 |
| LightGBM | **0.856 ± 0.004** | **0.812 ± 0.008** | 0.707 ± 0.009 |
| 随机森林 | 0.828 ± 0.006 | 0.776 ± 0.009 | 0.683 ± 0.009 |

时序外推验证（≤2024 训练 → 2025+ 预测）：逻辑回归 AUC 0.712、LightGBM AUC 0.715。PR-AUC 降到 0.32 左右，主要因为发表年份是第一大 SHAP 特征（删失伪迹：老论文有更长时间暴露撤稿，新论文"还没来得及翻车"），预测「未来才发生的撤稿」本质上更难。

大样本下的真实信号画像：翻车论文的**统计术语更多**（中位 1.0 vs 0）、标题反而更长（120 vs 110）、Meta 分析与基础研究的翻车倾向更高，而直觉上的"话说得太满"（夸张词）贡献几乎为零。

模型的定位是「发现可疑描述模式」的排序辅助，不能判定某篇文献是否会被撤稿，完整局限讨论见实验报告末尾。

这个模型已经接入检索链路：每次提问，返回的每篇文献都会实时带一个「风险 N%」徽章，是 LightGBM 预测的翻车概率，四档配色与证据等级同一套色系；特征构建与训练共用同一份词表代码，模型文件缺失时徽章自动隐藏，不影响主流程。

## 从「撤稿风险」到「可信性交叉验证」：这条研究主线到底在做什么

上一节的撤稿风险模型，是这条主线的**第一步**。它只能看「一篇文献自己说了什么」。但这有个明显的漏洞：一篇论文的标题、摘要写得再可疑，那也只是**它自己写的**。真正判断一篇论文靠不靠谱，还得看**别人怎么对待它**——有没有人引用它、引用它的论文后来有没有出事、作者以前干不干净。这就是「可信性交叉验证」要补上的东西。名字听着玄，道理很朴素：**不能只听本人一面之词，还要看别人怎么评价他。**

### 先讲一个绕不开的词：消融实验

这是理解整条主线的钥匙，用大白话说。

我们让模型看一篇论文的很多个「线索」，来判断它将来会不会被撤稿。线索有：发表年份、被引用次数、研究类型、摘要里有没有可疑措辞……一共二十多种。你自然会问：这些线索里，哪个是真有用的，哪个是滥竽充数的？

「消融」就是干这件事的方法，像做减法测试：**一次只留一类线索，看它自己单独能猜得多准。** 单独猜得越准，说明这线索越有用。

我们真做了这个测试，结果很反直觉：

| 只留哪一类线索 | 单独猜的准确程度 | 怎么看这件事 |
| --- | --- | --- |
| 发表年份 | 最高 | 看着最厉害，其实是**假线索** |
| 被引用次数等 | 第二 | 真正的客观证据 |
| 研究类型 | 中等 | 有点用 |
| 摘要措辞 | 最低 | 几乎没用 |

为什么「年份」单独猜反而最准？因为这是个**假线索，专门骗人的**。道理特别简单：一篇 2010 年的论文，有十几年时间被人慢慢发现有问题、然后撤稿；一篇 2025 年的论文，刚出生，还没来得及「被发现」。所以「越老的论文越容易被标记成撤稿」，这个规律学到的是「时间过得久」，而不是「论文本身造假」。靠这个去预测，等于作弊——它根本答不出「哪篇**新**论文将来会出事」这个问题。

**消融的价值就在这：它把模型里那个「看着最厉害、其实在骗人」的线索揪了出来，逼我们去找真正靠谱的证据。** 那个证据，就是下面要说的「引文信号」。

> 补充一个诚实的实验结果（`data/citation_signal_report.md`）：我们采了 7.8 万篇文献的 OpenAlex 引文信号，验证「引文信号能不能顶掉年份伪迹」。结论是——**简单的引文信号（被引次数、作者数）在预测「未来撤稿」上并没有赢过年份**（时序外推 PR-AUC：年份 0.578 vs 引文 0.194）。原因有两层：①「被引次数」本身也是删失的，老文献天然被引更多；②翻车文献往往是被大量关注、被争议后才撤稿，被引次数反而更高，单看引用数区分不了。这个负结果很有价值，它说明「可信性交叉验证」不能停在「数引用次数」这么浅，必须往「关系推理」走——引用了谁、被谁引用、作者历史、期刊声誉，这正是量级三要做的。

### 引文信号是什么，为什么比「论文自己说的话」更可信

「引文信号」就是**别人对这篇论文留下的客观痕迹**，主要从一个叫 OpenAlex 的免费学术数据库拿：

- **被引用了多少次**：一篇被很多同行认真引用的论文，和一篇没人理的论文，靠谱程度不一样
- **有没有被独立标记为撤稿**：OpenAlex 自己有一套撤稿标记，能和 PubMed 互相印证
- **有几个作者、发在什么期刊**：一个人偷偷写的论文，和一整个团队写的，可信度不同

为什么这些比「标题摘要」更可信？一句话：**标题摘要是作者自己写的，他想怎么写就怎么写；而「被谁引用、引用多少次」是别人留下的记录，作者自己刷不了。** 这就像查一个人靠不靠谱，不能只听他自己吹，要看他身边人怎么评价他。「交叉验证」四个字，就是「多找几个独立的人证」的意思。

### 量级一 / 二 / 三：这条主线分三步走

我们把整件事拆成三步，从小到大、从易到难：

**第一步（现在正在做）：先证明「引文信号确实有用」。**
不用把数据全采完，先采一批，做个对照实验，证明「引文信号」这个线索，真的能顶掉「年份」那个假线索，让模型在「预测未来」上真的变强。这一步就是将来论文的核心方法。纯用电脑自带的算力就够，**不需要买任何显卡**。

**第二步：把引文信号做成一个全量数据库。**
把 PubMed 三千八百万篇论文的引文信号都采下来，存成一个能随时查的库。它的价值不是「训练更大的模型」，而是三件事：① 给第三步当「谁引用了谁」的地图；② 给模型一个「正常论文长什么样」的参照；③ 变成能天天自动更新的活数据。做完这一步，就从「一次性演示」变成「能长期跑的系统」。

**第三步：用大模型做推理。**
让 AI 顺着「引用链」去追查：这篇引用了谁、谁引用了它、同一个作者还发过什么，把零散线索拼成一篇论文的完整「信用报告」。这里有个必须遵守的规矩：**测试的时候，只能用「模型没见过的新案例」来考它**。如果拿它见过的老案例去考，那测的是「背没背下来」，不是「会不会推理」，分数是虚的。

### 第三步要买显卡吗？（结论：发论文阶段，一张都不用买）

很多人一听「大模型」就以为要花大钱买显卡，其实分三种做法，差别巨大：

| 做法 | 要不要买显卡 | 大概花多少钱 |
| --- | --- | --- |
| 直接调用现成大模型的接口（把话喂给它，它回答） | **不用，零显卡** | 按字数收费，看一篇论文几厘到几分钱 |
| 自己训练一个小模型 | 要租一块高端显卡 | 一小时 8–15 元，跑几小时到一天 |
| 只做「给线索转成可比较的数字」这一步 | 一张中端显卡就够 | 甚至能用免费接口省掉 |

**给第一步（发论文）用，默认走「调接口」这条路，本机一张显卡都不用买。** 买显卡是等第二步做完、要大规模天天跑的时候才考虑的事。

### 采集 OpenAlex 数据的几个关键点（踩坑记录）

这一节写给「要复现或继续这个研究」的人，讲清楚数据到底怎么拿。每个点都配一句大白话解释：

**1. 免费的「钥匙」在哪、怎么用。**
OpenAlex 的数据免费，但从 2026 年 2 月起，**访问它必须带一把免费的「钥匙」（就是一段随机的字母数字串）**。钥匙在 <https://openalex.org/settings/api> 登录后生成。免费钥匙每天有 1 美元的额度，足够每天查约 1 万次。把钥匙作为参数传给接口就行。钥匙是私密凭证，不能进公开仓库（本项目的钥匙存在本地专属文件里，不进仓库）。
*大白话：钥匙 = 你在这家数据网站的「会员卡号」，免费领，带上它才有正常额度。*

**2. 为什么必须带钥匙，不带会怎样。**
不带钥匙的请求，会去蹭「你所在网络 IP 的公共免费额度」，这个额度几乎总是被别人用光，结果是**一直被限流、一个都查不到**。这不是代码写错了，是这家网站的设计：它靠钥匙区分「真做研究的个人」和「白蹭的」。所以带钥匙是必须的，不是可选。
*大白话：不带会员卡，就得和一堆陌生人抢公共的免费名额，抢不到就啥也查不了。*

**3. 批量查，别一篇一查。**
一次请求能同时查最多 50 篇（中间用竖线隔开）。七万八千篇，批量查只要约 1570 次，免费额度完全够。一篇一查会慢 50 倍，还更快被限流。
*大白话：快递一次取 50 个包裹，别一个包裹跑一趟。*

**4. 一个坑：文献编号要写成完整网址。**
查询条件里的文献编号，必须写成 `https://pubmed.ncbi.nlm.nih.gov/32015336` 这种完整网址，只写 `32015336` 是查不到的。
*大白话：地址要写全，光写门牌号不带路名，快递找不到。*

**5. 一个环境坑：本机 Python 连这个网站握手不稳。**
实测本机 Python 直接访问 OpenAlex 会报「握手失败」错误，但系统自带的 `curl` 命令很稳（6 秒就返回）。所以采集脚本改用 `curl` 来发请求，Python 只负责分批、并发、存文件。这是「换一条更稳的通道」的典型做法。

**6. 并发能快 30 倍。**
一条条串着采，每批要干等 5–6 秒网络往返，七万八千篇要 20 小时；改成 16 条线同时采，速度约 32 篇/秒，全量只要约 40 分钟。瓶颈是「等网络」不是「算不动」，所以同时多开几条线，收益特别大。
*大白话：一个窗口排队太慢，开 16 个窗口同时办，快 30 倍。*

## 技术选型

- 后端：FastAPI + Uvicorn（异步）
- 检索：BM25 纯 Python 实现，无 scikit-learn / nltk
- 数据源：PubMed E-utilities（esearch + efetch + elink，免费无密钥）
- 分词：英文按词 + 停用词过滤，中文单字 + bigram，无需 jieba
- 问题理解：PICO 四要素，规则驱动中英文双向词典匹配
- 研究设计识别：标题 + 摘要 + 发表类型的规则匹配，按优先级判定
- 结论极性 / 冲突检测 / 置信度：强短语优先 + 否定词感知，显式建模证据分歧
- 完整性检测：PublicationType + CommentsCorrections 元数据解析
- 答案合成：默认抽取式（证据等级 + 关键词密度 + 结论句加权）；接 OpenAI 兼容接口后升级为生成式
- 前端：原生 HTML / CSS / JS，无框架，无构建

## 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 启动（公司网络 / 沙箱需要代理时先 export PUBMED_PROXY=http://127.0.0.1:7890）
uvicorn app.main:app --host 127.0.0.1 --port 8000

# 3. 打开 http://127.0.0.1:8000/
```

不装密钥也能跑，默认走离线抽取式回答；网络不通时回退内置语料。

### 可选：接 LLM 升级为生成式

```bash
export LLM_API_KEY=sk-xxxx
export LLM_BASE_URL=https://api.openai.com/v1   # 任意 OpenAI 兼容接口
export LLM_MODEL=gpt-4o-mini
```

配置后回答改为生成式（RAG），不配置则自动回退抽取式。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /health | 健康检查，返回 PubMed 是否在线 |
| POST | /api/search | 检索 + 分类，返回文献列表与证据等级 |
| POST | /api/answer | 完整问答，返回回答 + 引用 + 证据结论（极性 / 冲突 / 置信度）+ 证据分布 |

```bash
curl -X POST http://127.0.0.1:8000/api/answer \
  -H "Content-Type: application/json" \
  -d '{"query": "metformin cardiovascular risk type 2 diabetes"}'
```
