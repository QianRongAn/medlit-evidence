# 临床检索与摘要评测协议 v1

## 独立性的范围

`evaluation/clinical_v1` 是新采集的真实文献快照和新问题，不复用训练表中的 PMID 或已有单测问题。先阅读原始摘要形成查询/PICO/文献标签，单独提交冻结，再运行应用。保留原始来源 URL、快照、哈希、冻结提交和实际应用代码哈希。不改变生产模型或应用规则。

它不是随机样本，不是临床专家双盲评测。标签和摘要判定由本开发者模型编写，可能存在认知偏差；临床人员独立复核仍待完成。文献出现在模型预训练中与否不可核查。现在公开后可作开发基准，后续应另建未见问题集用于独立验证。

## 标签规则

- **主题相关**：研究涉及所问干预与结局，含引用既往该结局结果的次分析。不同人群可主题相关，但不能因此判断临床适用。
- **严格PICO匹配**：在当前摘要可核对的范围内，研究人群、干预、明确对照和所问结局均匹配；结局仅背景提及不能当作该研究直接效果证据。未在问题明确的字段不自行添加；不要把单个试验的窄人群结论外推到所有人群。
- **查询PICO**：只标问题明确表达的四字段；英语规范概念一致比较，忽略大小写与空白。未出现的字段为空。应用把新药当作普通关键词检索，并不算已识别干预角色。
- **语境忠实**：输出完整陈述受到对应摘要支持，组别、方向、数字、单位、统计显著性、时间/背景及不确定性不被歪曲。逐字摘录不是自动通过。背景的未知状态不能变成试验完成后的当前结论；不完整数字比较计失败。
- **直接回应问题**：陈述提供所问人群/比较/结局的结果；只介绍方法/研究目的不计，错误人群不计，复合终点不能替代单独成分的效应。可忠实但不回应问题。
- **有效回答覆盖**：候选池内可回答的问题中，至少输出一条“忠实且直接回应”并来自预标严格匹配文献的结果。不代表整份回答所有条目均正确，也不是总体正确率。

单个输出句作为初步审核单元，多主张句只有所有主张都符合才判忠实。只核对冻结的原始摘要，未评全文、试验质量或医疗决策正确性。完整研究推论仍须阅读全文。

## 分母

返回文献主题相关率与PICO匹配率均为微平均：合格的“问题—文献”项数 / 实际返回项数（最多前5项）；空列表不记为100%。同时报告固定池召回率、可回答问题命中率、非空回答覆盖和有效回答覆盖，以暴露弃答。池内无证据的标签只指这12篇，不能解释为医学上不存在证据。

问题PICO完全匹配要求四字段全部正确；同时保留每字段 TP/FP/FN，不能依靠大量未提问的空字段抬高准确率。摘要忠实率分母只包含实际输出且全部审核过的句子；没有审核时为不可评估。输出26项句子中的双语重复不是独立观察。中英文按15组问题配对，来自10个试验家族，样本小且刻意选取，不报告总体泛化的置信区间。

## 执行

```bash
# 不覆写历史 run 和 review；输出必须使用新文件名。
python scripts/evaluate_clinical.py run --output evaluation/clinical_v1/new_run.json

# 未逐句复核时忠实率为空。
python scripts/evaluate_clinical.py score --output evaluation/clinical_v1/new_run.json

# 填写 new_run.review.json 所有条目的判定、理由和审核者身份后统计。
python scripts/evaluate_clinical.py score --output evaluation/clinical_v1/new_run.json --review evaluation/clinical_v1/new_run.review.json

# 对已保存基线重算指标，无需网络或密钥。
python scripts/evaluate_clinical.py score --review evaluation/clinical_v1/baseline_run.review.json
```

评测实际调用ASGI `/api/search` 和 `/api/answer`，运行原有离线BM25→筛选→抽取链路。只固定取数、不计算风险模型分数，抽取模式强制不调用LLM。没有全网 PubMed 检索候选，不能测在线检索召回。固定池中可能有与问题主题相近的研究，不代表覆盖了真实检索的全部困难负例。

生成式模式使用 `--mode llm`，配置原应用的 LLM 凭证后才能执行；无凭证直接拒绝，不能自动回退后宣称测得LLM分数。按真实 `mode` 分组，0条真实LLM输出时 `llm_faithfulness=null`。该模式会依原应用设置发送上下文给配置的服务，需逐句单独复核，不能复用抽取模式判定。

源数据/标签变动、运行文件被改、评审与run哈希不符、重复或缺失判定、外来PMID、未审核条目都会拒绝统计。已有run或review不得覆盖。CI检测结构、分母、盲点与实际ASGI执行，不把本基准上的准确率写成必须达到的测试断言。

## 专家盲审包

- `expert_documents_blind.csv`：360项文献对；只给问题、标题、PMID与来源，不展示初稿标签。临床人员填写主题相关、PICO匹配、理由及姓名。
- `expert_pico_blind.csv`：30个问题；四字段及理由空白，由评审者独立填写。
- `expert_claims_blind.csv`：26项真实输出；提供问题、句子、来源，独立填写忠实、回应性及理由。
- `corpus.json` 是本次判定对应的固定原始摘要；在线来源未来可能更新，审核应核对快照。

推荐两名具备相关领域知识的评审者分开填写，第三人裁决分歧，并报告原始一致率与分歧类型。当前尚无实际人工评审，不报告虚构的一致性分数。初稿 `judgments.csv` 和模型逐句判定应在盲审后才提供给审核者作分歧分析。

专家复核完成后保留 v1，另建版本导入最终标签、审核人、裁决理由并重新冻结哈希，再执行同版本应用。不要直接编辑旧标签、重算哈希来覆盖不理想的历史分数。

跨平台哈希：v1最初冻结于Windows，三份源/标签文件按UTF-8规范CRLF计算，以保留原始冻结哈希；应用及评测器代码按规范LF计算。校验时统一换行，其他字节改动仍失败。Linux检出不会改变数据身份，原始冻结提交与标签不变。
