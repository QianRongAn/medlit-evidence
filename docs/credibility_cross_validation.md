# 可信性交叉验证引擎 · 技术方案

> 目标：从「撤稿风险预测」（单信号）升级为「医学文献可信性交叉验证」（多信号 + 逻辑推理 + 关联分析），
> 把假的信息信号过滤掉，输出可解释、可追溯的可信度判断。
> 这是一个能发高引用数据集论文的方向，前提是把「数据集」和「测试集迭代」做扎实。

---

## 一、核心思想：从「预测撤稿」到「交叉验证可信度」

现在的撤稿风险模型只回答一个问题：**「这篇文献的写作特征，像不像会翻车的那种？」**

它有几个天生局限：
1. **单信号**。只看标题+摘要的写作风格，拿不到真正强的信号（图像重复、数据伪造都在正文）。
2. **混入了时间伪迹**。年份是最大特征（老论文暴露时间长），风险分其实在算「暴露时长」。
3. **是相关性不是因果**。它判断「像不像」，不判断「到底哪里假」。

「可信性交叉验证」的本质是换个问法：**「能不能用多路独立信号，互相印证或互相矛盾，从而定位『假信号』？」**

一条假论文可以伪造写作风格，但很难同时伪造：
- 引文网络里的矛盾（别人引用它、反驳它、撤它的痕迹）
- 作者的既往学术不端记录
- 它和同领域其他文献结论的系统性冲突

**核心机制**：假信号往往「单看正常，交叉看就露馅」。交叉验证的价值就在这里。

---

## 二、信号清单（多路独立证据）

| 信号 | 数据来源 | 实现难度 | 假论文为何难伪造 |
| --- | --- | --- | --- |
| 写作特征（已有） | 标题/摘要文本 | 低 | 风格可以模仿 |
| 引文网络矛盾 | OpenAlex / Semantic Scholar 引文图 | 中 | 引证关系是第三方累积的，难伪造 |
| 作者学术历史 | OpenAlex 作者-论文图 + Retraction Watch 数据库 | 中 | 既往撤稿记录抹不掉 |
| 期刊声望/撤稿率 | 期刊历年撤稿统计 | 低 | 期刊整体风气难短期改变 |
| 跨文献结论冲突 | 同主题文献的结论极性对比 | 中 | 需要系统性自洽，单篇装不了 |
| 数据可复现性 | 方法学结构（样本量、统计方法） | 低 | 数据造假会在方法学留下痕迹 |

## 三、技术栈选型（分三层）

### 第一层：数据层（信号采集）
| 组件 | 选型 | 理由 |
| --- | --- | --- |
| 文献元数据 | PubMed eutils + FTP baseline 快照 | 已有，零密钥 |
| 引文网络 | **OpenAlex**（免费、开放、带引用关系）或 Semantic Scholar API | 引文图是交叉验证的核心数据源 |
| 撤稿数据库 | **Retraction Watch Database**（可下载全量 CSV） | 作者/机构/期刊的既往不端记录 |
| 图存储 | **Neo4j** 或轻量 **NetworkX + SQLite** | 关联分析需要图结构 |
| 向量检索 | FAISS / pgvector（可选） | 跨文献「结论相似度」检索 |

### 第二层：推理层（逻辑推理 + 关联分析）
| 组件 | 选型 | 理由 |
| --- | --- | --- |
| 多信号融合 | LightGBM / XGBoost（监督）+ 规则引擎（可解释） | 树模型可解释，SHAP 能拆每个信号的贡献 |
| 逻辑推理 | **规则引擎 + 图谱查询**（Cypher / NetworkX 路径查询） | 「作者 A 有 3 次撤稿 → 其新论文风险升」这类可解释规则 |
| 关联分析 | 图算法（社区发现、共同作者、共同撤稿簇） | 发现「学术不端团伙」这种深层模式 |
| 结论极性 | 复用现有 evidence.py 的极性识别 | 跨文献冲突对比 |

### 第三层：输出层（可信度评分）
| 组件 | 选型 | 理由 |
| --- | --- | --- |
| 可信度融合 | 加权投票 + 置信度校准 | 输出分档等级标签（复用 5 色体系） |
| 可解释性 | SHAP + 证据链文本生成 | 「为什么这篇可信度低」要能追到具体信号 |
| 前端 | 复用现有 FastAPI + 静态页，加关联图谱可视化 | 图可视化用 ECharts / Cytoscape.js |

## 四、实现方法（分阶段）

### 阶段 1：把「写作特征」之外的信号接进来（1~2 周）
- 接 OpenAlex 引文图：每篇文献的施引/被引关系、被引次数随时间曲线（异常增长 vs 撤稿前的引文雪崩）
- 接 Retraction Watch 数据库：建立「作者 → 既往撤稿记录」映射
- 产出：`integrity_signals` 特征表，每篇文献多几列新信号

### 阶段 2：构建关联图（2~3 周）
- 用 NetworkX（或 Neo4j）建「论文-作者-期刊-机构」异构图
- 关联分析：共同作者簇、共同撤稿簇、期刊撤稿率异常
- 图特征：节点的中心度、邻居的撤稿比例、所属簇的异常度

### 阶段 3：逻辑推理规则 + 多信号融合模型（2~3 周）
- 规则引擎：可解释的「如果-则」规则（如「作者既往撤稿 ≥ 2 且 引文网络有撤稿雪崩 → 可信度降一档」）
- 监督模型：把多信号喂给 LightGBM，输出可信度概率
- 两者互补：规则保证可解释下限，模型提升上限

### 阶段 4：测试集 + 迭代（贯穿始终，发论文的关键）
- **标注测试集**：从撤稿/存疑 + 正常样本中，留出独立的、时间外推的测试集
- **指标**：不只 AUC，还要「信号消融」——逐个拿掉信号看性能掉多少，证明每个信号都有贡献
- **迭代**：用测试集暴露的短板，回头补信号

## 五、测试集迭代（你明确要求的，也是发论文的灵魂）

发高引用论文的数据集，关键是**「测试集要够硬、够诚实」**：

1. **独立测试集**：训练集和测试集按时间切分（用过去预测未来），避免「用未来信息预测未来」的假高分。
2. **信号消融实验**：报告「只写作特征」vs「+引文网络」vs「+作者历史」vs「全信号」的性能阶梯，证明交叉验证的增量价值。
3. **对抗样本**：找「写作风格正常但实际撤稿」的样本，测模型能不能靠其他信号捞出来——这是「交叉验证」区别于「单信号」的核心卖点。
4. **可解释性验证**：人工抽检高风险预测，看证据链是否合理，不是黑箱。

**这一步做扎实，数据集本身就能成为论文的贡献点**——一个「多信号、带测试集、带消融、带时间外推验证」的医学文献可信度数据集，目前是空白。

## 六、诚实边界（必须写进论文和产品）

- 这是「可信度排序辅助」，不是「真假判定器」。
- 最强的信号（图像重复、数据伪造）仍在全文里，题录层面拿不到，这是根本天花板。
- 引文网络信号有滞后性：撤稿往往发生在引文积累之后，对「未来会翻车的新论文」预测力有限。
- 模型的价值是「把可疑的模式筛出来给人工审查」，不是替代人工。

---

## 七、下一步建议（按价值排序）

1. **先接 OpenAlex + Retraction Watch**，把引文网络和作者历史两个信号加进来，这是「交叉验证」区别于现状的质变。
2. **建关联图**，做「学术不端簇」的发现。
3. **搭测试集 + 消融框架**，这是论文的骨架。
4. 全程用 demo 库验证速率和成本，避免重蹈「抓数据是墙」的覆辙。

---

## 附：为什么这个方向能发高引论文

- 学界对「论文工厂」「学术不端」越来越敏感，但工具普遍停留在「单篇文本检测」。
- 「多信号交叉验证 + 可解释证据链」是一个清晰的差异化，且能落成公开数据集。
- 你的背景（肿瘤/免疫 + 单细胞/多组学）正好是论文工厂重灾区，领域敏感度最高。
