# 项目审查与修复记录

审查及更新日期：2026-10-18；审查基线：`2d04433`。以下保留原始问题，并标明修复状态。范围：应用代码、前端、测试、训练/评估脚本与已提交报告。未进行临床有效性评估、在线负载测试、模型重训或引文实验复现。

## 问题按影响排序

### 1. P1：关键词极性被冒充为临床命题判定（本轮已修复输出）

位置：原 `app/evidence.py`、`app/synthesizer.py` 以及前端判定卡。

`classify_polarity` 无 query 参数；`increased risk` 永远判 against，`reduced risk` 永远判 support。分析函数直接按这些标签宣布“证据存在分歧”，没有检查结局、人群或对照。例：句子 A 为“Statin therapy increased risk of incident diabetes.”，句子 B 为“Statin therapy reduced cardiovascular risk.”，原代码会把不同结局标成相反证据。用户改成提问“是否增加糖尿病风险”也不会改变判定。

旧评分又将研究设计、数量、年份与这些标签组合为 0–100 分；上述两个合成句配 High 分级与 2026 年份，在 `2d04433` 基线可复现“存在分歧 / 置信度 84”。研究类型不等于结论正确率，这个分数未作独立校准。

修复：删除措辞极性分类及置信度公式，不输出自动支持/反对、冲突或分数。API 用 null 和显式 assessment_status 表示未评估；未评估不计作 neutral。保留来源摘录、研究类型和撤稿告警。页面、摘要句、历史记录与使用统计同步停止展示旧结论；说明文字持续可见。LLM 提示词改为逐篇整理，但模型遵循指令的正确性仍属第 3 项的开放问题。

恢复该功能的前提：带问题命题方向及 PICO 的人工标注集、独立测试集、否定/不确定性/多结局/亚组/比较方向用例，以及经过验证的弃权机制。当前修复是停止错误的自动判定，不声称已经实现临床语义理解。

### 2. P1：模型输出展示为“未来撤稿概率”（已修复展示及接口）

位置：`app/risk.py`、`static/app.js` 的风险徽章、`scripts/train_model.py`。

训练目标来自已收集的撤稿/对照样本，存在人工采样比例与年份删失。训练脚本没有给出特定预测时窗，也没有按真实使用人群校准概率。`predict_proba` 直接展示为“风险 N%”，不能解释成“这篇论文未来有 N% 概率撤稿”。

修复：API 改为 `research_model_score`、0–100 分、`calibrated=false`，删除风险等级。页面显示“研究分数 N / 100”，无百分号和风险分档，持续说明未校准、不代表未来撤稿概率。旧版概率载荷不展示；演示改写摘要不评分。无效模型数值被过滤，模型与标准化器须全部加载成功才报告就绪。未改变模型或重新训练；恢复概率展示仍需预测时点、观察窗、真实基率与校准验证。

### 3. P1：生成式输出的引用未经程序验证（引用校验已修复；语义验证仍未完成）

位置：`app/synthesizer.py:llm_answer` 与 `app/main.py:answer`。

服务直接返回模型字符串，未检查引用 PMID 是否存在于实际传入上下文中，也未逐条验证陈述由原文支持。提示词中的“不得编造”无法替代校验。上下文还有字符截断，不能仅用检索结果全集作为引用白名单。

修复：预算内只发送完整 JSON 文献记录，构建函数同时返回实际发送片段的白名单。模型须按条目返回 `pmid/text/quote`；逐项校验数据结构、白名单、正文无额外引用及对应原句存在。服务器为每项附加唯一可信引用。任何一项失败即丢弃整份生成结果、回退原文摘录，并返回原因；上下文为空时不请求模型。前端展示可点击 PMID、对应摘要原句与校验范围。测试包括超出文献上限、预算裁剪、撤稿、错误或遗漏原句、伪造源标记、夹带引用和无引用文本。

仍有边界：原句存在不证明生成摘要被原句蕴含，也不保证人群或临床结局适用。API 明确返回 `content_entailment=unassessed`，页面提示人工核对；不将来源校验称为内容或临床正确性验证。

### 4. P2：引文实验的指标解读和时间协议不足（评估代码已修复，前瞻数据待补）

位置：`scripts/evaluate_citation_signal.py`、`data/citation_signal_report.md`、训练及消融脚本。

PR-AUC 使用 PR 曲线梯形面积，未同时给 AP、测试集阳性比例和常量基线。常量预测的 PR 曲线有端点插值面积；不能把“年份 AUC 0.500 / PR-AUC 0.578”解读为有效区分能力。按发表年份划分但使用采集时的引文/标签，也不足以证明前瞻预测未来撤稿。原始信号文件未提交，当前无法完整复现对照实验。

修复：三个入口共用 AP、训练比例常量基线、Brier 与梯形面积；显式年份切点、同折配对、重复 PMID/类别/空集校验。新增严格固定观察窗协议，检查特征时点与标签可用日，排除未成熟随访。现有数据无法前瞻评估，明确拒绝，不再声称预测未来。23,287 条特征重跑模型与消融，旧引文报告标记历史、未伪造新数字。详见 [评估协议](evaluation_protocol.md)。折标准差不作为置信区间；独立时点数据与外部验证仍需补齐。

### 5. P2：研究类型识别易被摘要背景中的关键词抬高（已修复已复现规则问题）

位置：`app/study_type.py:classify`、`app/main.py:_annotate_docs`。

分类把标题、整篇摘要与发表类型拼在一起，按首个关键词命中。“This case report discusses a previous meta-analysis.” 即可先命中 meta-analysis、返回 High；即使 pubtypes 明确为 Case Reports 也不能覆盖它。

修复：明确发表类型精确匹配并优先处理；标题与摘要分开，泛化标注仅使用标题设计自述及自身方法描述补充。背景、既往研究、计划与无关子串不参与设计推断；不兼容设计标注保留未分级。通知分列 notice/N/A。仍属保守规则，不声称完整识别复杂研究设计；未修改风险模型特征。

### 6. P2：完整性关系类型覆盖不足（已修复已知关系及方向）

位置：`app/pubmed.py:_detect_integrity`。

函数接收 reftypes，却只使用 RetractionIn；ExpressionOfConcernIn、ErratumIn 等输入会返回 ok。现有测试只覆盖存疑/更正的发表类型，未覆盖这些关系分支。

修复：按 [NLM 定义](https://www.nlm.nih.gov/bsd/policy/errata.html) 处理撤稿、存疑、更正及重发正反关系。原文与通知分开标记，多状态及关联 PMID 同时保留。通知保留在来源列表但不作为研究证据，排除回答、LLM 和模型评分。已撤稿旧版不再影响修正后重发新版的状态；普通评论/更新/重印不直接触发问题标记。规则与固定 XML 回归见 [分类与完整性说明](classification_and_integrity.md)。

### 7. P2：检索相关性只需单个词重叠，PICO 未用于筛选（已接入保守词项筛选，临床语义仍未验证）

位置：`app/main.py:_query_tokens/_annotate_docs/answer` 与 `app/pico.py`。

原文与翻译后 token 拼接、按 BM25>0 选入候选；英文问题 token 会重复，任意单一关键词命中就能进入回答。PICO 只在响应中展示，不参与检索约束，更不保证人群/结局匹配。抽取式句子命中按子串计数，也可能在不相关词内命中。

修复：搜索与回答共用 query plan，去重排序词项；已识别的 PICO 和其余有效词项全部参与纳入检查。明确结局须在摘要出现，缺摘要不生成回答；未识别字段不凭空补齐，不能解析的条件明确弃权。结果、未纳入候选及逐字段原因分开返回；覆盖率不再按最高 BM25 归一化。抽取句和 LLM 引用原句也检查请求结局，离题但真实的原句会触发回退。修正泛糖尿病/2 型、新发疾病/既有人群、活性比较药物及英文子串混淆；离线先筛选后限量。规则和边界见 [检索与 PICO 筛选说明](retrieval_screening.md)。

尚未解决的边界：局部词项覆盖不能证明全文研究分组、比较关系与患者适用性一致；已有新来源模型标注基准初评，尚无独立临床专家标注集上的 precision/recall 评估。保留这一限制，不恢复自动临床判断。
