# 撤稿风险全量预标注 · GPU 与成本测算

> 目标：把「撤稿风险模型」从「实验室训练」升级为「全量预标注风险库」——对 PubMed 海量文献逐篇跑风险分并入库可检索。
> 本文回答三个问题：要多大 GPU？要多久？要多少钱？以及「其实 GPU 可能不是瓶颈」。

---

## 一、先纠正一个前提：现有方案不需要 GPU

当前风险模型 = **22 个手工特征**（标题长度、作者数、资助数、统计术语数、研究设计等）+ **LightGBM**（树模型）。

这套东西**完全跑在 CPU 上**：

| 环节 | 耗时（实测） |
| --- | --- |
| 2.3 万样本训练（5 折 CV + SHAP） | 几分钟 |
| 单篇文献推断风险分 | 微秒级 |

**结论：沿用现有方案，全量 3700 万条的风险分计算，瓶颈在「抓数据」和「存数据」，GPU 用不上。**

---

## 二、真正的瓶颈：抓数据（这才是墙）

PubMed eutils API 的硬限制：

| 项目 | 数值 |
| --- | --- |
| 全量记录数 | ~3700 万条 |
| 无 API key 限速 | 3 请求/秒 |
| 单次 efetch 上限 | 200 条 |
| 理论峰值吞吐 | ~600 条/秒 |

**全量抓取时间估算**：

| 方案 | 吞吐 | 抓完 3700 万耗时 |
| --- | --- | --- |
| 无 key（守规矩） | ~600 条/秒 | **约 17 小时**（但会频繁被限流/封 IP，实际 2~5 天） |
| 带 API key | 10 请求/秒 | 约 5 小时（仍需控制，NCBI 会人工审查滥用） |
| 官方 FTP 批量下载 | 一次性拉全量 XML 快照 | **推荐，数小时可完成，且不触发限流** |

> **关键发现**：全量数据不是靠 eutils 一条条抓的，PubMed 官方提供 **每年全量 XML 基线快照 + 每日增量文件**（`ftp.ncbi.nlm.nih.gov/pubmed/baseline/`，约 40 GB / 年），这是合规且最快的获取方式。

---

## 三、GPU 什么时候才需要：升级到「语义向量」

只有当特征从「22 个手工特征」升级成「摘要的语义向量」时，GPU 才有意义。

| 项目 | 数值 |
| --- | --- |
| 全量记录 | ~3700 万 |
| 单条摘要 token | ~300 |
| 编码模型 | PubMedBERT（110M 参数，比通用大模型小 1000 倍） |
| 单卡吞吐（A100 80G，fp16，batch=64） | ~2000 条/秒 |
| 全量编码耗时（1 卡） | **约 5 小时** |
| 8 卡并行 | **< 1 小时** |
| 向量存储（768 维 float16） | 3700万 × 768 × 2B ≈ **57 GB** |

**GPU 选型对比**：

| GPU | 显存 | 全量编码耗时 | 参考云价（按小时） | 适用 |
| --- | --- | --- | --- | --- |
| RTX 4090 | 24 GB | ~2~3 天 | 便宜 | 本地开发、demo |
| A100 80G | 80 GB | ~5 小时 | 中 | 一次性全量 |
| 8×A100 80G | 640 GB | < 1 小时 | 高（~$30/时） | 生产级、可重跑 |

**结论**：语义向量方案的 GPU 需求并不夸张——**1 张 A100 80G 跑 5 小时，或 1 张 4090 跑 2~3 天**即可全量编码。这远不是「大模型训练」的量级。

---

## 四、三种方案的成本全景对比

| 方案 | 特征 | 硬件 | 全量耗时 | 存储 | 模型上限 |
| --- | --- | --- | --- | --- | --- |
| **现有 LightGBM** | 22 手工特征 | 纯 CPU（8 核 32G 云主机即可） | 抓数据是瓶颈，算分秒级 | 每篇 ~200B，全量 ~7 GB | 中（AUC 0.856） |
| **语义向量 + 分类头** | PubMedBERT 向量 | 1×A100 80G | 编码 5 小时 + 抓数据 | 向量 57 GB + 元数据 | 高（有望突破浅层特征上限） |

---

## 五、推荐路线（务实落地）

1. **Demo（当前阶段）**：5 万篇子集，沿用现有 LightGBM，纯 CPU，当天出结果，实测抓取速率与存储。
2. **全量 v1**：用 PubMed 官方 FTP 快照（合规、最快）拿全量元数据，LightGBM 全量跑分，纯 CPU 云主机即可，存储 ~7 GB。**这一版根本不需要 GPU。**
3. **全量 v2（可选，追求模型上限）**：升级 PubMedBERT 语义向量，租 1 张 A100 跑 5 小时，存储 ~57 GB。GPU 需求明确：**1×A100 80G 足够，8 卡 <1 小时**。

---

## 六、成本速算（一次性）

| 项 | 现有方案 | 语义向量方案 |
| --- | --- | --- |
| 抓数据 | FTP 快照，~免费 | 同左 |
| 算力 | 8 核云主机 ~¥0.5/时 × 数小时 | 1×A100 ~¥30/时 × 5 小时 ≈ ¥150 |
| 存储 | ~7 GB（¥几毛/月） | ~57 GB（¥几元/月） |
| **一次性总成本** | **< ¥50** | **< ¥300** |

> 结论：这个项目的「全量化」成本极低，真正的投入是工程时间，不是硬件。GPU 需求「1 张 A100 跑几小时」量级，绝非大模型训练那种烧钱规模。
